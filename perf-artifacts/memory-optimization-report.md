# 第二轮：降低常驻内存

用户反馈上一轮 Go 版 CPU 约 0.5%、内存 161 MB、GPU 约 0.3%，C# 版内存约 14 MB。
检查确认当时运行的是本项目 `dist/CodingFire.exe`。上一轮的日志扫描和纹理复用修复
仍保留，但它们没有消除 OpenGL 窗口、驱动和字体库的常驻开销。

## 最终实现

- Windows 火焰改为 `UpdateLayeredWindow`，复用一张 32 位 DIB，直接使用原像素渲染器的输出。
- 悬浮卡片用 Windows GDI 绘制 Segoe UI/系统回退字体，不将整份字体和字形图集载入 Go 堆。
- 控制台保留 go-gui 控件、事件、布局与文字绘制，使用软件渲染和 GDI BitBlt 显示。默认路径不创建 OpenGL 上下文。
- 控制台的关闭按钮原来只调用隐藏窗口；现在真正关闭并销毁。最后一个文字窗口关闭时，释放 go-glyph 全局字体缓存，并在后台回收已释放对象的堆内存。
- go-glyph 本地副本基于 v1.25.2；新增缓存释放接口，保留原许可证。原缓存最多允许 384 MiB，空闲五分钟后才淘汰，和小型常驻桌面工具的需求不匹配。
- 火焰仍为 10 fps、余烬 4 fps；鼠标检测 20 Hz，悬浮统计 2 Hz。隐藏或熄灭时停止不必要的定时重绘。
- `CODINGFIRE_OVERLAY_BACKEND=gl` 保留旧渲染路径，便于兼容性诊断。

未使用 Windows 工作集裁剪 API 来降低任务管理器数字；改动减少实际资源，并释放已关闭窗口的字体缓存。

## 同机整进程对比

环境：Windows amd64，Go 1.27.1，Ryzen 7 5800H。
以两个独立的新进程运行同一个内存探针，比较 GL 路径与最终 Windows 位图路径。
探针读取相同位置的历史记录和本地数据源，所有写入均位于临时目录，不修改开机自启，
不显示窗口和托盘。固定火焰预览，依次创建悬浮卡片、设置控制台，再触发控制台关闭事件。
后台日志在测试期间可能继续变化，因此数值会有少量波动。

| 场景 | 原 GL 路径工作集 | 最终位图路径工作集 |
|---|---:|---:|
| 火焰运行约 8 秒 | 188.4 MiB | 32.5 MiB |
| 悬浮卡片 | 220.6 MiB | 33.5 MiB |
| 控制台打开 | 304.4 MiB | 181.7 MiB |
| 控制台关闭约 3 秒 | 270.2 MiB | 37.3 MiB |

最终路径对应的 Go 活跃堆约为：8.2、5.0、120.9、6.8 MiB。
原始日志：`memory-gl.txt`、`memory-all-native.txt`。

这些是带测试框架的进程工作集，不能直接等同于任务管理器默认“内存”列，
也不能把工作集、私有提交量和 Go 活跃堆混为一谈。尚未达到 C# 版反馈的 14 MB。
控制台打开时仍有字体解析、布局和软件画布开销；关闭后会释放。
新版在真实可见桌面场景的 CPU/GPU 百分比与风扇转速未做量化对比；DWM 桌面合成仍可使用 GPU。

## 运行

新产物：`../dist/CodingFire-lowmem.exe`。
先从托盘退出旧副本，再运行该文件。它沿用现有 Go 版设置和统计目录。
不要同时运行 C# 与 Go 版来比较占用。

复现探针（窗口始终隐藏，完整流程约 16 秒）：

```powershell
$env:CODINGFIRE_MEMORY_PROBE = '1'
$env:CODINGFIRE_OVERLAY_BACKEND = 'bitmap' # 改成 gl 可比较旧路径
go test ./internal/ui -run TestOverlayMemoryProbe -v -count=1
```

探针文件 `memory-bitmap.txt`、`memory-native-final.txt` 是中间方案的记录，
最终结果以 `memory-all-native.txt` 为准。
